# Современные GGUF-кандидаты: обновление на 28.10.2026

Статус: ограниченный refresh первичных источников; модели, проекторы и runtime не загружались, inference/Windows/WSL2 benchmark не выполнялся. Planner получил исключительную запись этого отчёта вместе с ARCHITECTURE.md и PLAN.md. Прежний список проверял существование старых артефактов, но не актуальность модельного ряда; он заменён. Qwen2.5-Coder-7B, Qwen3-8B, Qwen2.5-VL-3B и Gemma 3 4B — только legacy baselines, без загрузки по умолчанию. Старые лицензионные вопросы не блокируют новый shortlist.

Условия: личное некоммерческое использование; Windows 5600X / 16 ГБ RAM / RTX 3060 12 ГБ, WSL2 — первая гипотеза. Пользователей максимум 1–2, исходно одна очередь и один активный inference slot. Пользователь требует реальное сравнение с Gemma и предпочитает Unsloth GGUF. Автор конверсии не заменяет издателя базы, её revision или лицензию. Предпочтение — одна современная модель для coding/tool-use/RU/text+vision; отдельные text/vision профили допустимы после измерений. Heretic-style остаётся optional.

## Доказательства runtime и оставшиеся prerequisites

- **Qwen3.5 text:** [upstream src/models/qwen35.cpp](https://github.com/ggml-org/llama.cpp/blob/master/src/models/qwen35.cpp) явно распознаёт 4B/9B. Это реальный implementation evidence, а не HF app snippet. В [generic multimodal docs](https://github.com/ggml-org/llama.cpp/blob/master/docs/multimodal.md) и mtmd README имя Qwen3.5 не найдено; отсутствие имени не означает отсутствие поддержки. [Unsloth guide](https://unsloth.ai/docs/models/qwen3.5) содержит llama.cpp 9B примеры, family mmproj guidance и настройку thinking mode. Поэтому vision confidence — converter-author инструкции + доступный projector; конкретная пара/сборка/CUDA/WSL2 пока не проверены. В этом bounded refresh не установлен минимальный upstream release/PR для полного vision пути.
- **Gemma 4:** upstream [multimodal docs](https://github.com/ggml-org/llama.cpp/blob/master/docs/multimodal.md) явно перечисляет E2B/E4B, включая vision; [architecture registry](https://github.com/ggml-org/llama.cpp/blob/master/src/llama-arch.cpp) содержит gemma4. Это family support, не результат запуска выбранного Unsloth/QAT quant.
- **Granite:** тот же [upstream registry](https://github.com/ggml-org/llama.cpp/blob/master/src/llama-arch.cpp) содержит granite; издатель выпускает GGUF. Поддержку всех особенностей 4.2 thinking/template/tool round-trip ещё проверить; не приравнивать наличие architecture enum к пройденной интеграции. Для Ministral в этой задаче подтверждены карточки и файлы, а точная runtime/vision совместимость остаётся gate перед возможным лотом.
- Перед любым опытом закрепить commit/release llama.cpp, CUDA backend, необходимые guest libraries и выбранный model/projector/template/parser. Для WSL2 подтвердить Windows driver/CUDA access, общий RAM/VRAM запас и guest/host isolation по PLAN. Инференс только с локальными путями, без `-hf`/auto-fetch в продукте. Отдельный MTP/draft и speculative decoding не входят в baseline; их наличие в каталоге не добавляет разрешённый файл.

## Исключения из baseline и итог

- **30B+ MoE** (например Qwen3-Coder-30B-A3B, Qwen3-Coder-Next 80B, Qwen3.6-35B-A3B) не выбираются по active 3B как модели для 12 GB VRAM. [Официальный Qwen catalog](https://huggingface.co/Qwen/collections) и News сохраняют полные размеры; грубая нижняя оценка 30B × 4/8 = 15 GB сырых весов уже до overhead. Это причина исключения из default на Windows 16 ГБ, а не утверждение о невозможности любого экспериментального offload.
- Gemma 4 26B A4B хранит около 25.2B параметров по Google card, не 4B; 31B и Qwen3.8 27B также вне первых компактных лотов. Qwen3.8-27B не объявляется невозможной: это conditional поздний dense offload опыт после exact footprint/runtime/budget проверки. Агрессивные quants/сложный offload ради них не являются исходной стратегией.
- Legacy четыре модели прежнего shortlist не скачиваются по умолчанию. Перепроверка их старых лицензий и benchmark не нужны для этого решения. Heretic-style не получает выдуманного артефакта и не задерживает обязательные модели.

**Решение для будущего P1:** фактическое сравнение **A1 Qwen3.5-9B Q4_K_M + один F16 mmproj** и **A2 Gemma 4 E4B Unsloth Q4_K_M + один F16 mmproj**, последовательно, по отдельно разрешённым лотам. Gemma — обязательная часть сравнения по команде пользователя. B1/B2 — варианты уменьшения нагрузки; Q5/Q6/4B Q8, UD и Google QAT — только последующие обоснованные сравнения. Текущий результат не выбирает победителя и не разрешает ни одну загрузку. Минимальные paired vision smoke tests входят уже в P1; полный vision acceptance остаётся P6. Все обязательные coding/tool-use/RU/text/vision fixtures одинаковы для A1/A2. Для 1–2 пользователей сохраняются отдельные сессии, один активный запрос и очередь; два параллельных KV/слота не включаются без отдельного resource test.

## Расширение: большие модели, точные bytes и общий 100 GB потолок

Пользователь разрешил подготовить эксперименты с большими моделями/weights CPU offload, KV-in-RAM и KV quant отдельно, но Windows тесты состоятся позже. Приоритет компактного A1/A2 и обязательность Gemma сохраняются. Весь продукт с WSL overhead/пакетами/restore/trial/update должен занимать не более **100000000000 bytes**, не только model root. Вмещаемость полного комплекта не доказана.

Малыми первичными JSON metadata запросами от 28.10.2026 уточнены bytes A1 и A2: [A1 metadata](https://huggingface.co/api/models/unsloth/Qwen3.5-9B-GGUF/tree/main?recursive=false&expand=false) 5680522464 +918166080 =**6598688544**; [A2 metadata](https://huggingface.co/api/models/unsloth/gemma-4-E4B-it-GGUF/tree/main?recursive=false&expand=false) 4977171584 +990372672 =**5967544256**. Это remote bytes, не GPU/host memory.

L1 **Gemma 4 12B** Unsloth Q4_K_M+F16 =**7296977280 bytes**; L2 **Ministral 3 14B** Q4_K_M+F16 =**9117121376**; optional M1-Q3 **Qwen3.6-35B-A3B UD-Q3_K_S**+F16 =**16258479808**. Лицензии/релизы, exact file names, SHA/revision boundary, другие quants, первичные metadata URLs и память/задержка/WSL ограничения: [offload.md](offload.md). Эти кандидаты не default и не объявлены невозможными. A1+A2+L1 файловые наборы суммарно **19863210080 bytes**, но runtime/окружения/знания/копии/пик учитываются отдельно. Старое исключение 30B+ означает только отсутствие в default, не запрет измеренного ограниченного опыта M1.

D3.8 conditional dense добавлен по focused проверке Org от 28.10.2026: [Unsloth Qwen3.8-27B Files](https://huggingface.co/unsloth/Qwen3.8-27B-GGUF/tree/main), [Qwen base](https://huggingface.co/Qwen/Qwen3.8-27B). Rounded UD-IQ3_S +F16 ≈12.93 GB, UD-Q3_K_XL ≈14.03 GB, UD-Q4_K_M ≈17.43 GB; это не точные bytes и не resident memory. Эксперимент после M1 при обосновании и exact manifest/runtime/resource gates; A1/A2 остаются первым обязательным сравнением. Нельзя говорить, что поколения после3.5 не запускаются; для3.6/3.8 пока нет target результата.

Уточнение quant acceptance: пользователь опасается деградации ниже Q4; запрета на исследование не вводил. Q4/Q5 остаются baseline, Q3 — optional сопоставление большей модели с меньшей Q4/Q5 по неизменным code/tool/RU/vision критериям. Q2 не является выбранным default. M1-Q4 сначала проверяется по бюджету; отказ не даёт разрешения тихо перейти на Q3/Q2. Исследование Unsloth для3.5 не является измеренным качеством3.8; никаких новых benchmark runs здесь нет.
